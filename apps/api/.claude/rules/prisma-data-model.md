# Prisma and the data model

**Scope:** the schema, migrations, and every query that reaches Postgres.

## Rules

1. Models are `PascalCase` singular, fields `camelCase`, database tables and columns `snake_case` via `@@map` / `@map`. Ids are UUIDs generated by the application, not autoincrement integers — ids appear in paths, tokens and URLs and must not be enumerable.
2. Folders and files are both `Node` rows discriminated by `type`. Do not add a parallel table for files; every tree operation is written once.
3. `Node.path` holds the ancestor **id** chain (`/<rootId>/<childId>/`) and `depth` its length. Names never appear in a path, so a rename is a single-row update.
4. Anything that reparents a node rewrites the subtree path prefix and `depth` **in the same transaction**. Only the tree repository may write `parentId`, `path` or `depth`; a stale path silently corrupts sharing, search and deletion at once.
5. Uniqueness is enforced by the database, never by read-then-write. Sibling names use a unique index on `(parentId, normalizedName)`; catch the unique violation and map it to the domain error.
6. `normalizedName` is written by one shared normalisation function (trim, Unicode-normalise, lower-case). Two call sites normalising differently is a latent duplicate.
7. Index for the queries that exist: `(parentId, type, name, id)` for listing and its cursor, `(dataRoomId, path)` with `text_pattern_ops` for subtree prefix scans, unique `(token)` for shares, a GIN trigram index on `lower(name)` for search. Adding a query means checking the plan, not guessing.
8. Subtree work is one prefix query — aggregate, delete, search — never a recursive walk and never a query per level.
9. Wrap multi-row writes in `$transaction`. Collect the storage keys of files being deleted _before_ the delete, and release blobs after the commit.
10. Migrations are additive and forward-only, one per change, with a name that says what it does. Never edit a migration that has run outside a local database.
11. Select the columns a caller needs. Never return a `passwordHash`, a refresh token or a raw share token from a repository that feeds a response.
12. Raw SQL is permitted where Prisma cannot express the query (prefix aggregates, trigram matching). It is parameterised, always, and lives in the repository with a comment saying why it is raw.

## Examples

```prisma
model Node {
  id             String    @id @default(uuid()) @db.Uuid
  dataRoomId     String    @map("data_room_id") @db.Uuid
  parentId       String?   @map("parent_id") @db.Uuid
  type           NodeType
  name           String
  normalizedName String    @map("normalized_name")
  path           String
  depth          Int
  sizeBytes      BigInt    @default(0) @map("size_bytes")

  parent   Node?  @relation("NodeChildren", fields: [parentId], references: [id], onDelete: Cascade)
  children Node[] @relation("NodeChildren")

  @@unique([parentId, normalizedName])
  @@index([parentId, type, name, id])
  @@index([dataRoomId, path])
  @@map("nodes")
}
```

```ts
// subtree aggregate — raw because Prisma cannot express a prefix scan with FILTER
const [row] = await this.prisma.$queryRaw<AggregateRow[]>`
  SELECT count(*) FILTER (WHERE type = 'FILE')   AS files,
         count(*) FILTER (WHERE type = 'FOLDER') AS folders,
         coalesce(sum(size_bytes), 0)            AS bytes
  FROM nodes
  WHERE data_room_id = ${dataRoomId}::uuid AND path LIKE ${prefix} || '%'
`;
```

## Anti-patterns

- Checking `findFirst` for a duplicate name before inserting — two requests both pass.
- Walking `parentId` in a loop to build breadcrumbs.
- `include` pulling a whole subtree to count it in JavaScript.
- Writing `parentId` outside the tree repository.
- A migration that alters an earlier migration instead of adding a new one.
